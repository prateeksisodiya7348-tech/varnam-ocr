# Model card — Varnam OCR recognizer

## Overview

| Field | Value |
| --- | --- |
| Task | Line-level optical character recognition |
| Script | Devanagari (Hindi, Marathi, Nepali, Sanskrit) |
| Architecture | CRNN: 4x conv blocks + 2-layer BiLSTM + linear CTC head |
| Parameters | 4,160,025 for the 89-class charset (~16.6MB float32). Exact count printed by `ml.export_onnx`; do not quote a number the script has not printed. |
| Shipped artifact | `rec.onnx`, 15.9 MB **float32**. INT8 dynamic quantization was attempted and rejected: it emits `ConvInteger` nodes that onnxruntime's CPU provider does not implement, so the exporter load-tests the graph and falls back to float. |
| Input | 1 channel, 32 x 320 px, normalized to [-1, 1] |
| Output | Per-time-step class logits, CTC decoded |
| Runtime | onnxruntime CPU, 1 intra-op thread |
| Latency target | p95 <= 300ms per line on 1 vCPU |

## Intended use

Transcribing **line crops** of printed or handwritten Devanagari in documents,
forms, receipts and book scans. The API composes this model with a
projection-profile line segmenter; the model itself never sees a full page.

## Out of scope

- **Layout detection.** Column and table detection is heuristic, not learned.
- **Other Indic scripts.** Bengali, Tamil, Telugu etc. are not in the charset and
  will produce wrong but plausible-looking glyphs, which is worse than failure.
- **Severely degraded input.** Torn, water-damaged, or < 100 DPI scans.
- **Handwriting outside the training distribution** — see *Limitations*.
- **Anything safety-critical** (medical records, legal filings) without human review.

## Training data

Expected composition, listed by the manifest's `slice` column:

| Slice | Source | Notes |
| --- | --- | --- |
| `synthetic` | `scripts/gen_synthetic.ps1` (GDI+ render of `data/corpus_hi.txt`) | Correctly shaped Devanagari, random font size, jitter, danda. Used to bootstrap a model and to verify the full train→export→serve path. |
| `printed_clean` | IIIT-ILST / synthetic renderings | Clean digital renders |
| `printed_scan` | CVIT-OCR, scanned books | Noise, skew, bleed-through |
| `handwritten` | Devanagari Handwritten Character Dataset | Isolated characters; needs line composition |
| `phone_photo` | Self-collected, labelled via the feedback loop | Real deployment distribution |
| `mixed_layout` | Forms, receipts | Numbers and Latin tokens mixed in |

**On the synthetic slice:** a model trained only on GDI renders learns glyph
shapes and spacing but never sees scanner noise, paper texture, camera blur or
pen strokes. Expect CER on synthetic to be far better than on real photographs.
Report the slice it was measured on or the number means nothing.

**Why GDI and not Pillow:** Pillow on Windows ships without libraqm, so it cannot
shape Devanagari — it draws an i-matra after the consonant instead of before it.
Those images look plausible to a non-reader and are wrong to the model. GDI+ uses
Uniscribe and shapes correctly.

**Licence:** each upstream dataset keeps its own licence. Check before shipping
weights trained on them, and record the exact commit or snapshot hash used.

## Evaluation

Do not trust a number that is not in `docs/EVALUATION.md`, and that file is
generated by a command, not written by hand:

```bash
python -m ml.eval --manifest data/eval_manifest.csv --engine onnx
```

Metrics are reported per slice, not aggregated, because a single mean hides the
case that actually matters (usually handwriting or phone photos).

## Limitations and known failure modes

1. **Conjunct clusters.** Rare three-consonant conjuncts (e.g. `स्त्र`) are the
   top confusion source; the training distribution under-represents them.
2. **Matra confusion.** `ि` vs `ी` and `ु` vs `ू` differ by one stroke and are the
   most frequent single-character errors. A larger input height (48) is the
   mitigation to try first.
3. **Latin fallback.** Mixed Hindi/English lines degrade because the ASCII class
   set is small and under-trained.
4. **Long lines.** Lines wider than 320px are downscaled, losing thin strokes.
   The API splits at word gaps, but a dense single-word line can still overflow.
5. **Handwriting.** Character-level training data does not teach natural
   connected writing; real handwriting CER is materially worse than print.

## Ethical considerations

- OCR of personal documents is high-risk: a wrong digit in an ID or an amount can
  cause real harm. The API surfaces per-line confidence so a human can review.
- The feedback loop stores corrections. It must not be used to train on
  documents users did not consent to share; the deployment keeps only text and
  never the original image beyond the viewer's lifetime.
- No attempt is made to identify individuals from their handwriting.

## Reproduction

```bash
python -m ml.data.prepare --images data/raw --manifest data/train_manifest.csv
python -m ml.train --manifest data/train_manifest.csv --charset data/charset.txt
python -m ml.export_onnx --checkpoint artifacts/best.pt --charset data/charset.txt \
    --out services/api/models
python -m ml.verify
```
